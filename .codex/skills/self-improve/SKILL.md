# 卡面前景与字形纠错

曾出现的错误：看到卡面上的商标和字样，就把「ときのそら」、hololive、小图标及版权字样都放进八达通卡的前景 SVG。用户指出这些只属于该张联名卡的设计，换背景时应一并移走。

以后先依据用户本次要求，把元素分成「新背景上仍需复用」和「旧卡面专属」两组，再生成矢量图。**元素看起来像 Logo，不等于它应进入前景。** 默认只保留机构/支付服务及支付网络等可复用的身份标识，以及截图实际可见的遮蔽卡号尾号；角色、联名主题字标、卡面专属小图标、版权字样和装饰留在背景。用户明确指定保留或剔除某项时，按其当前要求调整，不把本例变成所有卡的一刀切规则。

八达通截图的验收例：前景只有「八達通 Octopus」；不含「ときのそら」、hololive、下方小图标、`© 2016 COVER Corp.` 和角色插画。该截图没有可见尾号，不编造号码。导出前对照原图和用户要求逐项检查前景清单及预览，确认没有把应随背景替换的标记带入 SVG/PNG。

## 融色时锁定已认可字形

曾出现的错误：先把旧 foreground.svg 和 upload.png 的截图描摹路径当成原版，导致换色后仍保留扭曲笔画；随后又自行匹配字体重建。用户认可本次清晰效果，但明确要求今后不再自行改字体。字形修正与换色是两项不同工作，不能从“换色”推断改字授权。

八達通 Octopus 当前认可的字形底稿是项目内 Assets/八達通 Octopus/背景融色-粉蓝白-清晰字形/foreground-clean.svg。之后以它为只读源：SVG 仅改填充色，保留路径、字距、位置、比例和透明度；透明 PNG 仅改 RGB，逐像素保留 alpha。旧 Assets/八達通 Octopus/foreground.svg 和 upload.png 不再作为融色的字形依据。若用户提供的新源与认可底稿或清晰参考不符，先核实并说明，不得擅自选字体、重打字或重新描摹。

验收时分别看纯色底上的标识近景和真实背景叠加图。背景若已含旧字样，重影要单独标明，不能据此改动字形。
